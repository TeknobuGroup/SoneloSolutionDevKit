# Changelog

## [Unreleased]

### Added
- Kit 4.8: **the UAT block says who to sign in as, in both places a tester looks.** A round is slow because the tester keeps signing out and back in as somebody else, not because the cases are hard. Cases now name the login profile first in the module (`"Supplier — Quotes"`, `"Site admin — Approvals"`), which is how the hub groups them and how the spreadsheet and client-facing round exports come out, so one login's cases arrive as a batch; and again as the first instruction in the steps, because the module heading is above the fold and the steps are what gets read. "A supplier user with at least one open quote" is runnable; "a user" is not. One login per case - a case needing a supplier to submit and an admin to approve is two cases, or the tester signs in twice inside one case and can record a clean result for neither. Credentials never go in a case: name the profile, never an email and password, because the hub is not a password manager and cases are exported to clients. Numbering and the profile are reconciled rather than left to fight ("01. Supplier — Quotes").
- Kit 4.8: **a push is not reported until it has been checked.** A push that times out, returns 200 with nothing created, or reaches the wrong project looks identical to a successful one in a transcript. The block now tells a session to read the module back and report the number the hub returned, not the number it sent, and to say which cases are missing rather than rounding up to "pushed successfully". With the trap that makes the number readable: the response field is called `created` but counts inserts **and** `source_ref` refreshes, so a clean re-push of twelve unchanged cases reports twelve and reads like twelve duplicates.
- Kit 4.8: **never print the key** - not the value, not a prefix, not "the key starts with", because it reaches transcripts, commits, PR bodies and issue comments. Plus the Windows route to a key that is set but absent from a running session's environment: read it from `HKCU\Environment` and pass it as an environment variable rather than restarting. Two traps in that one line are documented because both fail silently - `reg query`'s raw output contains the key, so it must be captured and never echoed, and `grep` needs `-a` or it treats that output as binary and reports no match at all, which reads as "no key set" rather than as a grep problem.
- Worklog 1.18: **tokens are recorded against the day they were spent.** Each session carried one total, so the cost of a session spanning five days could only ever be smeared across whatever range you asked about. `tokens_by_day_by_model` is collected per session per local day; a range now takes exactly its own days. The day rides inside the usage tuple rather than being bucketed as the transcript is read, because `rec["usage"]` is keyed by `requestId` and merged with `dict.update` across transcript files - bucketing at parse time would have counted every resumed or sidechained record twice. Slices collected before 1.18 have no such map: their spend is apportioned across days by the effort recorded on each, and both the report and the dashboard say so rather than printing an estimate as fact.
- Worklog 1.18: **the dashboard reloads itself** (`DASHBOARD_RELOAD_S`, default 180s - deliberately the same as `STOP_THROTTLE_S`, because reloading faster than the collector can produce new data only costs the reader their hover, their selection and their place; `dashboard_reload_s` in `~/.claude/worklog.json` to change or `0` to switch off). It is opened as a `file://` page, so it cannot fetch its own data - reloading is the only way to pick up a re-render, and the collector already re-runs every three minutes. The range, the selected project and the scroll position survive the reload (sessionStorage, falling back to `window.name` where an opaque file origin forbids it), and it does not reload while the tab is hidden or a control has focus.
- Worklog 1.18: the dashboard's `dayMinutes()` and the report's `session_day_minutes()` are now pinned against each other by a test that lifts the JavaScript out of `DASHBOARD_HTML` and runs it under node, comparing both against the same seven sessions - midnight-crossing bursts, a gap opening before midnight and closing after, and a total that cannot divide evenly across its days. The two implementations of this rule had never been checked against each other; they had already drifted once. Skipped, not failed, where node is absent.
- Kit 4.7: **`.githooks/checks` lines can name the paths they care about** - `[src/* *.css] npm run test:ui` runs only when the push touches one of them, and a line with no prefix always runs. A stylesheet stops paying for the back-end suite; in this repo that is a ~200s suite skipped on a docs-only push. `ci.yml` now generates its steps from `.githooks/checks` (prefix stripped), so every line still runs somewhere even when every local push skips it - that is what makes scoping safe rather than a hole, and it was not true when the feature was first written. An unknown or uncomputable changed set runs everything: this may only ever skip work it is certain is irrelevant.
- Kit 4.7: **a `spike/`, `draft/` or `proto/` branch reports outstanding work instead of blocking the session.** Nothing that fails irreversibly is relaxed - the secret scan, the protected-branch refusal and the migrations guard are unchanged on every branch. Be clear about what it costs: the debt is reported at the time and recorded nowhere, `pipeline-state.sh` sees only uncommitted work so committing hides it, and no gate recomputes it on merge. A spike branch is unreviewed work; the only thing that reviews it is `/post-change` on the branch you merge into.
- Kit 4.7: **`uat-writer` pushes to UAT Hub.** The kit was shipping two mutually exclusive instructions and enforcing both: the generated `CLAUDE.md` said "do NOT write them to a Markdown file", the agent said "you write `docs/uat/<branch>-<date>.md`", and `ci-gates.yml` failed the PR without that file. A session obeying CLAUDE.md pushed to the hub and then failed its own gate. The agent now pushes the cases and writes a short record - project, module, count, and a `source_ref` table - so the gate passes and a reviewer sees scope without a second copy that goes stale on the next re-push. It defers to the `## Writing UAT` block for the field contract rather than restating it, because two shipped copies of something the endpoint enforces drift silently. A repo with no hub project still gets full cases in the document, and says so.
- Kit 4.6: the generated "Writing UAT" block tracks the hub's updated `docs/AGENT_PROMPT.md` - 83 lines, still a verbatim copy with only the slug substituted. Two additions matter to a session: **re-push after you rebuild something** (a case is a definition that outlives a testing round, so pushing again updates the definition and leaves the case untested in the current round - it does not destroy last round's evidence), and, under "if the push is refused", check the boring cause first: a key set with `setx` **after** Claude Code was already running is absent from the MCP server's environment, so the hub answers "invalid or revoked api key" for a key that is perfectly good. Restart before suspecting the key, and never rotate on one 401.
- Kit 4.6: `/update` — a slash command for taking the latest release on this machine. The machine update was only reachable through the session-start nudge; dismiss that and there was nothing to type. It runs `update`, reports the version it moved from and to, and then points on to `refresh`, which is what actually carries a release into a repo. `install` writes it, `uninstall` removes it.
- Kit 4.6: `refresh --uat-project <slug>` — the rollout verb can now set a repo's UAT Hub project. Without it, `refresh` wired a repo to its folder name and the only in-kit correction was `apply`, which also rewrites CI, the environment doc and the design contract and checks out the work branch: far too much blast radius for one string. The slug is recorded in `.teknobu.json` **only** when explicitly passed, so `refresh` still owns no repo keys it was not handed, and a later plain `refresh` no longer reverts to the folder-name default.
- Kit 4.5: **UAT goes to UAT Hub, not to a Markdown file.** A repo the kit sets up can push UAT test cases to https://testing.teknobugroup.com with no further wiring. `apply` writes `.mcp.json` registering the hub's `uat-hub` MCP server (merged into any `.mcp.json` the repo already has - another server, and any other top-level key, is left exactly as it was; a file that will not parse is reported rather than replaced, and anything replaced is backed up under `.claude/.backup/`). `CLAUDE.md` gains a managed "Writing UAT" block copied verbatim from the hub's `docs/AGENT_PROMPT.md` - it states a field contract the endpoint enforces, so it is a copy, not a paraphrase, and a test pins the field names. `UAT_HUB_KEY` is documented in `.env.example` with an empty value, and `doctor` reports whether it is set. Decision recorded in docs/decisions/0006. Adds 28 unit tests (173 total).
- Kit 4.5: the project slug is asked for once - `apply --uat-project <slug>`, and question 5 of `/repo-setup` - and remembered in `.teknobu.json` as `uat_project`, so later applies do not re-slug the repo. It defaults to the folder name, which is safe rather than a guess: the hub refuses a push to a slug it does not know rather than creating a project, so a repo with no hub project yet is inert, not broken. The hub URL and the path to the uat-hub checkout are constants in the kit - one internal hub, one checkout location, and a config knob nobody turns is one more thing to fall out of step.
- Kit 4.5: **the key is never written.** `.mcp.json` carries the literal `${UAT_HUB_KEY}`, expanded from the environment when Claude Code starts the server. `.mcp.json` is committed into client repos that may be handed over, and one key covers every project, so a literal in one repo's history would expose push access for the whole estate. `NoLiteralKeyEverWritten` puts a real key in the environment and greps everything the kit produces.
- Worklog 1.17: the dashboard shows **agent-hours** beside elapsed time. agent-hours is effort - each session's own active time, summed, so five sessions working an hour each reads as five agent-hours; elapsed is wall clock with any session active, where those same five count once. The two were already computed differently in different places with only one of them labelled, so the same day could be read as two numbers with no way to tell which was which. Measured on this machine: 337h effort against 248h elapsed over 28 days, peaking at 5 concurrent sessions.

It does refresh the kit's own gates (`.github/workflows/ci-gates.yml`, `.github/pull_request_template.md`) — they are part of the pipeline — and names every file it replaces rather than counting them; the repo's own `ci.yml`, environment doc, `.env*`, design contract, branches and worklog are untouched. `apply --update-pipeline` still works; `refresh` is what the nudge, `update` and `/repo-setup` now recommend.

### Fixed
- Kit 4.7: **a multi-ref push no longer scopes against a partial changed set.** A range that could not be resolved emitted nothing and was unioned with the ranges that could, so the set still looked non-empty and scoping engaged against one missing whole branches - a first push of `prelive` alongside a spike branch skipped the migrations suite and the hook exited 0. The computation is all-or-nothing now: one unresolvable range disables scoping for the whole push. The invariant had been holding per-range, not per-push, and no test reached that path.
- Kit 4.7: **`--no-renames`.** `git diff --name-only` reports only a rename's destination, so `git mv` a file *out* of a scoped tree and the scoped check was skipped - the commonest way a UI or migration suite actually breaks.
- Kit 4.7: **`ci.yml` reads `.githooks/checks` at run time** rather than baking its lines at `apply` time. Baking meant editing the file - which its own header invites - left a line running nowhere until someone re-ran `apply`, and interpolating lines as `run:` steps put them under `bash -e`, where a deliberate local no-op like `[ -d e2e ] && npx playwright test` exits 1 and turns CI red. A line containing `: ` would also have broken the YAML.
- Kit 4.7: the spike-branch disclosure rides an **exit 2**, once, then allows. Moving it to stdout did not work: a Stop hook's stdout is transcript-only and its stderr is fed back only on exit 2, so the message that makes the escape defensible still never reached the session. It now uses the two-strike valve the gate already had.
- Kit 4.7: the shipped `CLAUDE.md` no longer describes the design-only rule that was reverted - it had been contradicting its own reviewer table three paragraphs later.
- Kit 4.7: `sample/githooks/checks` regenerated; it still carried a v1.0 header and the claim the new one replaced.
- Kit 4.7: **scoped checks skipped every path deeper than one level, silently.** `for g in $globs` word-splits *and* pathname-expands, so `[src/*]` was replaced by whatever happened to exist one level down: a change to `src/pages/app.css` was skipped, a change under `supabase/migrations/` was skipped, and a *deletion* was skipped because the path was no longer on disk to expand into. The hook reported success either way. `set -f` around the match. The feature's own 15 tests passed throughout because every one used a one-level path whose file still existed, where the expansion happened to produce the changed filename - depth of test data mattered more than number of tests.
- Kit 4.7: the changed set is built with `core.quotePath=false`, so a push whose files have accented names no longer skips every scoped line. The same defect was fixed in the pre-commit hook in 4.6 and not carried across to this one.
- Kit 4.7: the spike-branch disclosure goes to **stdout**. A Stop hook's stderr reaches the session only when it exits 2, so writing it to stderr on the exit-0 path meant the one thing making that escape defensible - stating the debt rather than hiding it - never happened. `session-brief.sh` already carried the comment explaining exactly this.
- Kit 4.7: `mktemp` failing now means "run every line" rather than a guessable path in a world-writable directory; an uncomputable changed set already means run everything.
- Kit 4.7: `.githooks/` and `tailwind.config.*` wake `security-reviewer`. The file that decides which checks run should wake the reviewer whose job is checking that they do, and a tailwind config is executed on every build, in CI and on every machine.
- Kit 4.7: the `security-reviewer` trigger catches ordinary React auth naming (`useAuth.tsx`, `AuthProvider.tsx`), which the path-shaped pattern missed, without matching `author.ts` or `Author.ts`.
- Kit 4.6: **the pre-commit hook no longer disables itself on a non-ASCII path.** git quotes a path containing non-ASCII bytes (`"cafÃ©/.mcp.json"`) unless told otherwise, and no `case` arm matched the quoted form - so every rule in the hook silently no-opped for any repo with an accented directory name. A literal hub key and an AWS key both committed cleanly from a folder called `café`. Pre-existing, and it defeated the env-file block, the key-material block, the size limit and the secret scan at once.
- Kit 4.6: **`protected` from a repo's `.teknobu.json` is validated before it reaches generated shell.** `work_branch` was regex-filtered in kit 4.1 with the comment that option-shaped values from a cloned repo must never reach git argv; `protected` sat on the next line, unfiltered, since v3.2 - and it lands inside double quotes in `.githooks/pre-push` and inside a YAML list in `ci.yml`. A cloned repo whose config held `main"; touch /tmp/PWNED; #` executed that on every push after `apply`. A string value also became `['m','a','i','n']`.
- Kit 4.6: **the kit does not act on a `.teknobu.json` it cannot read** - `apply` and `refresh` stop and say what to fix. Three narrower guards preceded this and each closed one hole: the first saved the file itself, but `WORK_BRANCH` and `PROTECTED` had already fallen back to this machine's, and `apply` then regenerated `pre-push`, `ci.yml`, the environment doc and the branch from them, so a repo protecting `production` quietly stopped protecting it; the slug fell through to the folder name, re-pointing a live repo at a different hub project. One rule replaces all three. A config that is valid JSON but not an object is treated the same way, which changes v4.3 behaviour deliberately: a list carries no branch model either.
- Kit 4.6: **`apply` no longer replaces a `.teknobu.json` it cannot parse.** The guard went into `refresh` and not `apply`, so fixing one of the two writers fixed nothing on the heavier command: a config with one stray comma was rewritten with this machine's defaults, losing `work_branch`, `protected`, `generated_types` and any key of the repo's own, with no backup and a report row reading `updated`. Because `use_repo_config` reads the same file the same way, the generated `pre-push` hook then stopped protecting a branch the repo had listed - and the config asserted the loss as truth. `use_repo_config` now says when it is falling back to this machine's branch model instead of doing it in silence.
- Kit 4.6: the server path is `${HOME:-${USERPROFILE}}/uat-hub/mcp/server.mjs`. **`HOME` is not a Windows environment variable** - it is absent from both User and Machine scope in the registry, and was visible in testing only because that shell was launched from Git Bash, which sets it per process. So the earlier verification could not have detected its absence and the claim built on it was wrong. `claude mcp list` accepts the `:-` default form, nested included (a bare unset `${VAR}` draws "Missing environment variables"; `${NOPE:-${USERPROFILE}}` draws nothing), which shows the syntax is parsed and satisfied - not that the resolved path is right. If it is not, the failure is the same as any wrong path: the server does not start and the session uses the HTTP endpoint.
- Kit 4.6: the generated environment doc no longer tells operators to hand-edit the `args` path. That instruction predated the self-healing rewrite, so following it produced a state `check` and `doctor` report as broken and the next `refresh` reverts. It now says to move or symlink the checkout instead, and says why the path self-heals.
- Kit 4.6: `check`/`doctor` label the `.mcp.json` row `(uat-hub server, as the kit writes it)`. It said `placeholder intact`, so a v4.5 repo whose placeholder *was* intact and whose `args` had drifted was told the opposite of the fact that would have helped.
- Kit 4.6: **the `.mcp.json` rule parses the file instead of matching text against it.** Three rounds of review produced four working bypasses, every one of them a consequence of the approach rather than of the regex: `grep -vF <hub url>` dropped any line *containing* the hub URL (so `testing.teknobugroup.com.evil.example`, a domain anyone can register, defeated it by construction); replacing that with a `sed` extraction only compared the **last** occurrence on a line, so a decoy value later in a one-line file laundered a redirect; a `\u004b` escape in the field name skipped the `grep` pre-filter entirely, and a `grep` miss fails **open**; and `command`/`args` were never checked at all, though they name the process Claude Code launches with the shared key in its environment. The hook now reads the staged blob with python - already a hard dependency, already used by `stop-gate.sh` - and compares all four fields structurally. An earlier entry in this release claimed both fields were "extracted and compared exactly"; that was not true for a line carrying more than one occurrence, and this replaces it.
- Kit 4.6: **example files are scanned for credential *shapes*, never for "has a value".** The rule that blocked a filled-in value blocked five of seven realistic template lines - among them Supabase's own published `.env.example` line, `API_KEY=changeme`, and `PUT_YOUR_LONG_API_KEY_VALUE_HERE` - and every one of those lands the developer on advice to run `SONELO_SKIP=1`, which turns off the rules that work. That is a control training people to disable it. A real `uath_`, `AKIA`, `sk-`, JWT or PEM in the same file still blocks; the detection that matters is unchanged. `name.example.ext` files (`wrangler.example.toml`, `docker-compose.example.yml`) count as templates too, which they did not before.
- Kit 4.6: `doctor` says when `HOME` is unset, because that is what `${HOME}` in `.mcp.json` depends on. Claude Code reports an unset variable rather than expanding it to nothing (verified with `claude mcp list`), so the server simply does not start - but the operator should be told why rather than discovering it.
- Kit 4.6: **`.mcp.json` names the server as `${HOME}/uat-hub/mcp/server.mjs`.** It was an absolute path resolved on the machine that generated it, so every client repo carried a developer's username in its git history and the path was wrong on every other machine. Claude Code expands `${VAR}` in `args` exactly as in `env` - verified with `claude mcp list`, which validates the reference and warns only about variables that are unset - so the committed file is now machine-independent, and `mcp_ok` can compare it exactly instead of by suffix (`./tools/uat-hub/mcp/server.mjs` satisfied a suffix test and is a redirected launch target).
- Kit 4.6: **an unreadable `.teknobu.json` is never replaced.** The fix for "refresh discards the slug when there is no config" reintroduced the `.mcp.json` bug one file over: `read_json` returns `{}` for unparseable and absent alike, so `refresh --uat-project` rewrote a config it could not read, losing `work_branch`, `protected` and `stack` with no backup and no message. `use_repo_config` reads that file, so the next `apply` would have regenerated hooks and CI against this machine's work branch instead of the repo's.
- Kit 4.6: a recorded `uat_project` that is not the hub's shape is **folded, not discarded**. v4.5 wrote that key from the folder name verbatim, so every repo in a `CamelCase`, `under_score` or `dotted.name` folder held a value the new rule rejects - and falling through to the folder name would have silently re-pointed a live repo at a different hub project. `MediaStack` becomes `mediastack`; the output names both. Only a value shaped like something the kit itself wrote is folded, so an injected string is still refused rather than normalised into use.
- Kit 4.6: `SLUG_RE` is the hub's own constraint, copied from its `projects_slug_format` check - `^[a-z0-9]+(-[a-z0-9]+)*$`, 2 to 64 characters. The looser pattern accepted a single character, a trailing hyphen and doubled hyphens, all of which the hub refuses, so the kit wrote slugs into `.mcp.json` and `CLAUDE.md` that failed later at push time where the cause is much harder to see.
- Kit 4.6: `--uat-project` is validated by argparse, before any file is touched. `refresh --uat-project 'Bad Slug'` used to replace all 34 pipeline files and *then* exit, printing neither its summary nor where the backups went.
- Kit 4.6: **the kit no longer preserves a hand-edited MCP server path** (superseded in the same release by the `${HOME}` path above, which removes the churn that fix was buying) - a fix from this cycle's own first review round, reverted in its second. Preserving `args` stopped the committed file churning between developers, but it turned a redirected `node` target into a persistent one: it survived `refresh`, ran at session start with `UAT_HUB_KEY` in its environment, and `mcp_ok` reported the repo as standards-complete. `args` is rewritten to the canonical path every run, so tampering self-heals. Churn is the lesser problem; the real answer is a machine-independent path, which is recorded as an open decision.
- Kit 4.6: `mcp_ok` checks `command` and `args`, not only the key and the URL, and returns `False` instead of raising on a hostile shape - `{"uat-hub": "hijack"}` crashed `check`, `doctor`, `apply` and `refresh` with an `AttributeError`.
- Kit 4.6: the `.env*.example` rule catches `export FOO=`, leading whitespace, a value on its own line and a value inside a comment; example files are no longer skipped by the generic scan either, which was a second independent bypass. It now fires only on names that look like credentials, so `NODE_ENV=development` in an ordinary example file is not blocked - a scanner that cries wolf is how people learn to reach for `SONELO_SKIP`.
- Kit 4.6: a `.mcp.json` whose `UAT_HUB_URL` points anywhere but the hub is refused at commit. `mcp_ok` detects it, but only when someone runs `check` or `doctor`; the hook catches it as it is written. Pinning the host inside `mcp/server.mjs` remains the durable fix and is a change in the hub repo.
- Kit 4.6: the secret pattern's key-name arm matches no-underscore forms (`hubkey:`) as well as `FOO_KEY`. The `uath_` arm is confirmed against the hub's `mint_api_key`, which issues `uath_` plus 64 hex characters.
- Kit 4.6: the reviewer-trigger table in the generated `CLAUDE.md` names `.mcp.json`, matching what `pipeline-state.sh` actually computes. The table is what briefs every session, so the two disagreeing meant the briefing was wrong in every repo.
- Kit 4.6: **an unreadable `.mcp.json` is no longer overwritten.** `read()` returns `None` for a file it cannot decode as well as for one that is absent, so `mcp_json` took the *create* branch on a UTF-16 `.mcp.json` - what PowerShell 5.1 redirection produces on Windows - and replaced every other MCP server in a committed file, with no backup, reporting `created`. It now branches on `path.exists()` and reports the file instead. `read`/`read_json` also decode `utf-8-sig`, so a BOM is no longer diagnosed as a syntax error. Found by a retrospective code review of the released v4.5.
- Kit 4.6: **the secret scanner can see a UAT Hub key.** The pre-commit patterns matched AWS, Anthropic, OpenAI, Stripe, Google, Twilio, JWT, PEM, Slack and GitHub shapes but nothing resembling `uath_...`, and `UAT_HUB_KEY` matched none of the four trigger words - so the one credential covering the whole estate was the one the kit's own hook would not stop. Worse, every `*.example` file was skipped by both loops, and v4.5 had just added `UAT_HUB_KEY=` to every repo's `.env.example`. Now: the hub prefix and `*_key` are matched, `.env*.example` is blocked if any value is filled in, and a staged `.mcp.json` whose `UAT_HUB_KEY` is not the `${UAT_HUB_KEY}` placeholder is refused outright.
- Kit 4.6: the UAT Hub slug is validated before it is spliced into CLAUDE.md. It comes from `.teknobu.json`, which is committed and whose edits `codechanged` filters out of the reviewer trigger, and it lands inside the managed block that carries the session's standing instructions - so an unchecked value containing newlines, or the block's own end marker, was a way to write instructions into every session in a repo. A bad value from the file is ignored; a bad one typed by a person is an error.
- Kit 4.6: `splice()` no longer doubles a file with damaged markers. An end marker with no start - a botched merge - paired with the real block's start and re-emitted everything between them: 435 bytes to 8.8 KB to 16.3 KB over three runs, duplicating the repo's own prose. It now pairs backwards from the last start that has an end after it.
- Kit 4.6: `refresh --uat-project` records the slug in a repo that has no `.teknobu.json`. The guard short-circuited on an absent or empty config, so the slug reached `.mcp.json` and `CLAUDE.md`, was never recorded, and the next plain `refresh` reverted both to the folder name - the exact regression the flag was added to prevent.
- Kit 4.6: `vercel` withholds `KIT_ENV_KEYS` from the Preview variables it pushes, and says so. `.env.example` now documents `UAT_HUB_KEY`, so copying it across to `.env.<work>` was the obvious motion, and this is where it would have left the machine.
- Kit 4.6: `check`/`doctor` parse `.mcp.json` instead of matching a substring, so a file whose key has been pasted in as a literal, or whose `UAT_HUB_URL` has been redirected to another host, no longer reports as standards-complete. `.mcp.json` now also triggers the security reviewer.
- Kit 4.6: `/repo-setup` passes the slug it asked for on the `refresh` path, not only on `apply`; the kit stops reverting a hand-edited server path in `.mcp.json`; a discarded non-object `mcpServers` is named in the report; other MCP servers kept during a merge are listed; `cmd_update` validates zip member paths before extracting an archive whose `repo_setup.py` it then executes; and the generated UAT block tells sessions never to echo the key and to refuse any host but the hub.
- Kit 4.6: **the shipped commands now run in PowerShell.** Every generated `PRELIVE.md`/`STAGING.md` told the operator to run `python ~/.claude/sonelo/repo_setup.py vercel ...` and `... protect`. PowerShell does not expand `~` for a native command, so python resolved it against the working directory and both died with `No such file or directory` — on a kit whose stated first-class platform is Windows. Now `python "$HOME/..."`, which works in PowerShell and sh alike. The same fix lands in README's `update` line. A test scans the module so no new template can reintroduce it.
- Kit 4.6: `uninstall` removes `/landing` and `/update`, not just `/repo-setup` and `/new-repo`. `landing.md` had been written by `install` since v4.0 and never removed, so it outlived the kit it belonged to. Worklog-only mode clears all four for the same reason.
- Kit 4.6: `sample/PRELIVE.md` regenerated — it was still stamped `teknobu-kit v1.1` and pointed at `~/.claude/teknobu/repo_setup.py`, a path renamed in v4.0. The sample is meant to show what the kit writes; it had been showing what the kit wrote four releases ago.
- Worklog 1.17: **elapsed time no longer counts an idle session as working.** A session with no recorded bursts fell back to its whole span, so one left open for three days counted as three days of activity. On this machine that put 24h of Claude Code against 18 and 19 August and overstated the 14- and 28-day elapsed figures by about 49 hours. The stand-in interval is now clamped to the active minutes the session actually recorded. Pre-existing and it always fed the report's day column; found by design review when the number was promoted to a dashboard card.
- Worklog 1.17: the report's day-table column is now `Claude Code (elapsed)` and the single-day header says `elapsed ... (concurrent sessions count once)`. Both were bare "Claude Code active" and read as effort. The paragraph explaining the difference was only printed when ActivityWatch or presence data existed, so a machine with neither shipped the column with no explanation at all; it is now always printed.
