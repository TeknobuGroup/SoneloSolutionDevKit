- **The restart trap, found the hard way and worth knowing before the estate sweep:** reloading the VS Code window (or restarting the chat panel) restarts the *extension host*, which re-spawns the MCP server - so it connects, and looks fixed. But the extension host inherits its environment from the VS Code **main** process, whose environment block is fixed at launch, so a variable set afterwards is still absent and `${UAT_HUB_KEY}` is sent to the hub as a literal. Only a full application quit refreshes it, and the reliable route is to quit and then run `code .` from a newly opened shell, so the environment is inherited from a process that has just read the registry. `Get-Process Code | Select StartTime` tells you in one line whether a restart actually happened.
