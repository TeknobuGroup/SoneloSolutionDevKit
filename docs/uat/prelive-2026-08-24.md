# UAT — prelive -> main — 2026-08-24

**Branch:** prelive  **Environment:** local machine with kit installed  **Prepared by:** Claude Code  **Status:** awaiting sign-off

## What changed

Two major changes ship in this pull request:
1. The repo has been refreshed to Sonelo standards kit v3.2, introducing a complete development pipeline: git hooks that enforce commit format and protect main/prelive branches, CI gates via GitHub Actions, a change management structure (docs/STATUS.md, docs/decisions/, docs/UAT_PLAN.md), and complete project documentation (CLAUDE.md, PRELIVE.md, README-SETUP.md).
2. Worklog agent v1.13 bumped to v1.14: the dashboard's Agents card and weekly markdown reports now group agent usage by project (bold project totals, individual agents below), agents display friendly persona names (e.g. "Stephen - Tech Nerd") with raw IDs on hover, share bars show proportional wall-time on a fixed scale, and a new 36-test stdlib unit suite validates the agent-name map and report grouping.

## Preconditions

- Machine with Python 3.8+ installed.
- The worklog agent installed on this repo (`python worklog_agent.py install` has been run, or auto-mode is enabled).
- One or more Claude Code sessions logged in ~/.claude/projects (generate test data by running at least one session in this repo).
- A ~/.claude/worklog.json file with at least `{"pot": "<path>"}` (or rely on the default ~/Worklog).

## Not covered here

- **Database migrations and Supabase changes**: The refresh includes docs/rules/supabase.md but no new migrations or edge-function changes; those are out of scope here.
- **Actual Claude Code integration testing**: The UAT assumes the worklog agent is already installed and running within Claude Code; testing hook invocation and response throttling is deferred.
- **ActivityWatch or presence-tracking validation**: The agent collects desk time and logon/lock/unlock events, but UAT here focuses on agent grouping and naming; AW/presence correctness is out of scope.
- **Cost calculation and pricing**: The config accepts a prices map; pricing correctness is not tested here.
- **Edge-function and auth rules**: CLAUDE.md references multi-tenant RLS policies and edge-function JWT validation, but those are not new; they are documented for governance only.
- **Historical data migration**: If an old worklog.json with a hardcoded pot path exists, the agent auto-migrates; this edge case is not tested in the UAT (it is a one-time operation).
